# 附录 A 术语表

正文讲过的名词都收在这里。分三张表：第一张是全书类比的固定对应，第二章起不再重复解释；后两张按用途分组收术语，一句话说它是什么，标它在哪一节讲过。

## 一、师傅队伍：全书类比对照

这本书用一支修灯师傅的队伍讲整套系统。对应关系是固定的，全书通用。

| 队伍里的人 | 系统里的东西 | 讲过 |
|---|---|---|
| 师傅的脑子 | 模型（model），只会想，不会动手 | §01 |
| 一整套人马 | 外壳（harness） | §01 |
| 拧螺丝的 | 工具（tool：读文件、写文件、跑命令） | §01 |
| 记笔记的 | 会话记录（session log） | §07 |
| 把门的 | 权限与沙箱（permission、sandbox） | §07 |
| 领班的 | agent 循环（agent loop） | §07 |
| 临时工 | 插件（plugin） | §07 |
| 排班表 | 装配清单（assembly manifest） | §07 |
| 公司最里面那一层 | 内核（kernel） | §07 |
| 直接点名找小张 | 消费方直连实现 | §07 |
| 换掉他要动几个人 | 改动半径 | §07 |
| 公告栏 | 事件总线（谁都能贴，谁都能看） | §09 |
| 公司规矩、部门规矩、工位纸条 | 配置三层覆盖，小的压大的 | §06 |
| 四套编制 | 四种形态（标准、PTC、极简、创造） | §06 |
| 备了替补的位子 | 接缝（有第二个实现的能力位） | §06 |
| 总账与抄件 | 日志是唯一事实，其余都是派生 | §11 |
| 门禁卡入职发、离职收 | 注册即副作用，卸载即撤销 | §10 |

## 二、构件与角色

| 术语 | 一句话解释 | 讲过 |
|---|---|---|
| 外壳（harness） | 模型之外、让它能干活的一整套 | §02 |
| 框架（framework） | 材料店：给材料，怎么盖随你 | §02 |
| 脚手架（scaffolding） | 图纸铺：给空架子，盖完就拆 | §02 |
| 插件内核 | 内核只留原语，其余皆是插件 | §07 |
| 服务键 | 一项能力占一个稳定名字 | §08 |
| 事件总线 | 横向通信的唯一通道 | §09 |
| profile（形态） | 一份具名组装，本质是一份名单 | §06 |
| bundle（组合包） | 可复用的配置分发单元 | §06 |
| patch（修改条） | 按名字定位一行，整块替换 | §06 |
| 宿主 | 四种入口同进一个门的那一层 | §05 |
| 子代理 | 领班叫来的外援小队 | §12 |

## 三、机制与判断

| 术语 | 一句话解释 | 讲过 |
|---|---|---|
| 核心不变式 | 模型提议，外壳授权、执行、记录、恢复 | §02 |
| 必答题 | 循环、上下文、工具接入、会话持久、权限沙箱 | §03 |
| 选答题 | 内核空置、模型插件化、日志可重放 | §03 |
| 改动半径 | 换掉一个组件要动几个地方 | §07 |
| 幽灵状态 | 拆一半留一半，旧登记还挂着 | §10 |
| 仅追加日志 | 只往后写、不改旧行的总账 | §11 |
| fork / resume | 笔记复印一份，从那一页接着写 | §11 |
| 三道闸 | 收紧、审批、隔离 | §14 |
| 故障安全 | 出岔子时默认落在更严的那一档 | §14 |
| 五条判据 | 不看代码判断一套系统做到没有 | §16 |
