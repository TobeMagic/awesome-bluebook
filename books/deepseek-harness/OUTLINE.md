## 一、两份参照物对齐

### 1.1 橙皮书的真实目录（《从开机到拆开》，119 页）

```
序幕 §00 序章：探索未至之境
Part 1 进门  §01 十分钟，让它干成第一件活
            §02 它被允许碰什么
            §03 四种模式，人话版
            §04 我从 Claude Code 搬过来，哪些能直接用
Part 2 主线  §05 每一次运行都有迹可循
            §06 一次任务到底多少钱
            §07 它给自己长出一只手
            §08 让模型写程序，以及那笔反直觉的账
            §09 让它自己干完一件长活
Part 3 地基  §10 skill、MCP、插件，到底谁管谁
            §11 两个插件都想管文件编辑，谁赢
            §12 它出过什么事
Part 4 收    §13 一个几乎全由 AI 写出来的代码库长什么样
            §14 它在赌什么，代价是什么
            §99 附录
```

**可提炼的三条规范**

1. **部名是动作**：进门 / 主线 / 地基 / 收。读者一眼知道自己在哪个阶段。
2. **节标题是具体场景或问句**，不用抽象名词。
   - 「它被允许碰什么」「两个插件都想管文件编辑，谁赢」「它出过什么事」「它在赌什么，代价是什么」。
3. **收尾必谈代价**。§14 不谈成绩，谈「它在赌什么，代价是什么」。

## 二、v2 的三个病根

| 病 | 具体表现 | 后果 |
|---|---|---|
| 缺 Related Work | 全书没有一处在讲「别人怎么做」 | 读者无法判断 DSH 的选择是必答还是选答 |
| 全景给晚了 | 「六层全景」排在第 3 部，前面挡着五条抽象主张 | 读者不知道这些主张长在地图哪一块 |
| 五条主张是平行关系 | §03–§07 都叫「主张 N」，粒度完全相同 | 镜头不推进，读起来像五条并列口号 |

**第四病（用户第二轮指出）**：标题都在**宣告结论**，不在**提出问题**。
读者扫一遍目录就知道答案了，没有往下读的理由。

---

## 三、节标题三律（v3.1 新增规范）

1. **标题要是一个问题，不是一个答案。**
   - 反例：同一件事只存一份（答案）→ 正例：同一件事，为什么只能存一份（问题）
   - 反例：怎么知道它真的做到了（半答半问）→ 正例：不看代码，怎么知道它真的做到了
2. **标题里要有具体的对象、数字或动作。** 抽象名词一律换成能想象的东西。
   - 反例：装配与实现分开 → 正例：装上去的每一样，都要能干净地拆下来
   - 反例：难在哪：四件一直在变的事 → 正例：难在哪：能力在变、模型在换、环境不可信、任务还老断
3. **陈述句只在反常识、有悬念时才用。** 平铺直叙的结论一律改成问句。
   - 可用陈述：内核里是空的，连 agent 循环都是插件（反常识，有冲击）
   - 不可用陈述：横向只走事件这一条路（只是陈述一条规矩）

## 四、v3.1 目录

### 序章

**§00 最中间的那一层，可以整块抽走**

具体场景开场：把系统最中心的一层整个抽出，别处一行都不用改。
不设小结，只留钩子——这件事为什么可能。

### 第 1 部 · 进门（4 节）—— 这件事是什么，难在哪

| 节 | 标题 | 讲什么 | 递进到哪 |
|---|---|---|---|
| §01 | 模型明明会写代码，为什么还是干不成活 | 从聊天到干活，差的是外面那一圈 | 给出问题 |
| §02 | harness 到底是什么，和框架有什么不一样 | 词的本义（马具）；行业公式「模型 + 外壳 = 智能体」；外壳 vs 框架 vs 脚手架；外壳里装了几样东西 | 给出对象 |
| §03 | 同样是外壳，为什么三家造出三种东西 ★ | DSH / Claude Code / Codex CLI 八维度对比；落到「Claude Code 卖成品，Codex CLI 卖接口，DSH 卖插座」 | **给出坐标** |
| §04 | 难在哪：能力在变、模型在换、环境不可信、任务还老断 | 四道难题 | 给出理由 |

> 本部只讲难处，不讲解法。

### 第 2 部 · 先看一眼（2 节）—— 整栋楼长什么样

| 节 | 标题 | 讲什么 |
|---|---|---|
| §05 | 拆开它，六层各管什么 | 先给地图，不给理由。有哪几层、各叫什么、谁挨着谁 |
| §06 | 同一套东西，为什么能装出四种形态 | 三层覆盖（全局/项目/目录）；四种形态（标准/PTC/极简/创造，差别只有一条——装了哪些插件）；能换的位子与不能换的位子 |

### 第 3 部 · 拆内核（5 节）—— 五个房间各放什么

**这五节的递进链条：划分 → 寻址 → 通信 → 生命周期 → 状态。**

| 节 | 标题 | 讲什么 | 链条位置 |
|---|---|---|---|
| §07 | 内核里是空的，连 agent 循环都是插件 | 什么放进内核、什么留在外面；判据是「会不会被换」不是「重不重要」 | 划分 |
| §08 | 用一样能力，只写它的名字，不用管它在哪 | 使用方只写字符串名字，由装配方兑现；名字活着，位置可以变 | 寻址 |
| §09 | 两个插件之间，为什么不直接喊话 | 横向不直连，走事件；谁发的谁收的不重要 | 通信 |
| §10 | 装上去的每一样，都要能干净地拆下来 | 注册即副作用，卸载即撤销。改一半留一半是最坏的结果 | 生命周期 |
| §11 | 同一件事，为什么只能存一份 | 单一事实源；其余视图都是照着它长出来的 | 状态 |

### 第 4 部 · 走一遍（2 节）—— 一次调用经过谁

| 节 | 标题 | 讲什么 |
|---|---|---|
| §12 | 一句问话进来，中间经过了谁 | 端到端走一遍，各层怎么配合 |
| §13 | 一次工具调用，要过哪五道工序 | 为什么不直接执行，非要做成流水线 |

### 第 5 部 · 碰边界（2 节）—— 哪里会塌，代价是什么

| 节 | 标题 | 讲什么 |
|---|---|---|
| §14 | 它被允许碰什么：三道闸 | 正着讲：权限怎么收、什么要等人点头、沙箱画在哪 |
| §15 | 它出过什么事：四个真实案例 | 反着讲。含沙箱逃逸案例（CVSS 9.4）。官方文档自陈沙箱「不保证隔离，也不防止破坏」 |

### 第 6 部 · 收（2 节）—— 能带走的几条判断

| 节 | 标题 | 讲什么 |
|---|---|---|
| §16 | 不看代码，怎么知道它真的做到了 | 几个能自查的问题 |
| §17 | 它在赌什么，代价是什么 | 必答题与选答题；选了插座路线，成本转给了谁 |
