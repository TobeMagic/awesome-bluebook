> **规格**：中文为主 · 16 节 + 4 附录（6 部）· 图占比 ≥40% · 输出 PDF / EPUB / HTML
> **状态**：**第二版完稿**（重排为「背景 → 主张 → 架构 → 运行 → 边界 → 带走」，正文不含代码细节，51 张 SVG）
> **当前版本**：v261003（v261002 为「源码导读」旧版，已归档到 `fragments-v1/`）
> **溯源基准**：commit `639ed015397290b3745d163aafe02ffee4aa3f84` · 2026-09-29 · `dsh-0.2.0-rc.2`（**只留在仓库文档里，不进书**）
> **License**：MIT（与官方仓库一致）
>
> **成书产物**：`deepseek-harness-bluebook.html`（单文件，封面 + 6 部题图 + 目录 + 20 节，51 张图全内联）

## 一、差异化定位（不可动摇）

花叔已有同主题橙皮书（1,319 stars），**必须错位，不可正面竞争**。

| | 花叔橙皮书 | 蓝宝书 01 |
|---|---|---|
| 回答什么 | 我装上之后会发生什么 | 它为什么被设计成这样 |
| 素材来源 | 亲手跑（129 行启动清单、原始会话日志） | 源码统计 + 官方架构文档 + 论文 |
| 载体 | 文字 + 截图 | **流程图驱动** |
| 深度方向 | 竖向：用透这个产品 | 横向：抽象出通用范式 |
| 保质期 | 短（预览期快照） | 长（架构范式不易过时） |

**一句话定位**：从一个能干活的外壳，讲到一套能搬走的设计。

**读者收获**：不是"会用 Harness"，而是**"看懂所有 agent harness，并知道自己的系统该怎么改"**。

## 二、可信度策略（因为无实测）

不能用「我用下来最大的感受是」。第二版把信任的来源整个换了：

1. **书内自证** —— 口径当场讲完，不留「自己去看某个文件」的指引。书是唯一交付物
2. **能搬走** —— 每条设计都落到「换成别的做法会丢什么」「这条能搬去哪个项目」
3. **代码细节有去处** —— 正文一律用角色名，包名/路径/键名统一沉到附录 D

> 旧版靠「来源可溯 + 可复现统计」建信任，结果把书写成了源码导读。
> 第二版把可溯性从正文移到附录：想核的人有地方核，不想核的人读得到判断。

**写作风格相对花叔的唯一改动**：
花叔是「有体验就断言」→ 蓝宝书是**「标明出处 + 给出可验证路径」**。

**已查定的三处表述边界（全书沿用，不得改口）**：

1. **「一切皆插件」不是官方原话**，是本书概括。官方原话是「产品的每一部分都是插件……」与
   「不存在需要打补丁的特权内核：扩展 dsh 的方式是把插件挂载到其他插件旁边」。
   凡引用必须标出哪些是官方原话、哪些是本书概括。
2. **「没有特权内核」≠「什么都能换」**。92 个 ctx 键里 core 55 个（单实现、无替换位）、
   seam 33 个（其中只有 15 个已有 ≥2 个实现）、service 3 个、bundle 1 个（即 `ctx.agentLoop`）。
   准确说法：所有东西都按插件装配，但不是所有东西都有现成的第二个实现。
3. **包数口径 = 316**，对应 `pnpm-workspace.yaml` 声明的 `packages/*/*`。
   递归数 `packages/**/package.json` 会多出 9 个分组级 manifest，得 325。书中一律用 316。

**出图方式**：全部走 `tools/build_figures.py`，产物在 `figures/fig-N-N-<name>.svg`。

**自检**：`ls figures/*.svg` 的每一张都要能在某个模块的 `FIGURES` 里找到条目，否则是孤儿图。

## 五、质量门（适配"无实测"）

沿用橙皮书 5 道门，第 4 门做关键改造：

| 门 | 检查什么 | 蓝宝书特别要求 |
|---|---|---|
| 1. 内容/事实审校 | 架构描述是否符合官方口径 | 每个架构断言必须能指到文档/源码位置 |
| 2. 风格审校 | 去 AI 腔 | 禁用"我用下来感觉"类伪体感 |
| 3. 细节打磨 | 句长 15–25 字、图注完整 | 每张图必须有图注 + 一句话解读 |
| 4. **事实核查（独立）** | **强制 WebSearch / 读源码** | **核查对象是官方口径与统计数字，不是体感** |
| 5. 全书一致性 | 术语、ctx 键、包名全书统一 | 建术语表，禁止同物异名 |

> 第 4 门仍必须独立于第 1 门：写作者与审校者共用同一模型知识库，
> 错误会在同一信息茧房里反复传播。核查员**必须联网或读源码**，不能靠记忆。

**额外加一道（蓝宝书专属）：来源标注检查** ——
每一节末尾列出本节结论的出处（文件路径 + 章节名），缺失即打回。

## 六、写作规范要点

继承橙皮书风格 DNA，改动一处：

| 维度 | 规则 |
|---|---|
| 句长 | 15–25 字/句 |
| 人称 | 可用"我们"（指作者+读者共同查证），不用伪第一人称体感 |
| 数字 | 用可核验的具体数字，标明统计口径 |
| 图 | **图是主骨架不是配图**；每图配图注 + 一句"这张图说明什么" |
| 引用 | 用 `§NN` 交叉引用；结论后标注 `〔来源：文件路径〕` |
| 禁用词 | 综上所述 / 值得注意的是 / 强大的 / 革命性的 / 在当今这个…时代 |
